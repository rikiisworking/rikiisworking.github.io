  • API optimizationAPI最適化 Cut a high-load endpoint from ~5 s to 700–800 ms (≈85%) by reworking data structures, caching and logic. Moved some REST APIs to Server-Sent Events, which reduced API calls and server load. 高負荷エンドポイントのレスポンスタイムを約5秒から700〜800msへ短縮（約85%改善）。データ構造・キャッシュ戦略・ロジックを見直し、一部REST APIをSSEへ移行することでAPIコール数とサーバー負荷を削減。
  • Pipeline latencyデータパイプライン遅延改善 Cut processing latency from 5–10 minutes to 5–10 seconds (30–120×) by optimizing the Pub/Sub layer and reworking batch processing. Pub/Sub基盤の最適化とバッチ処理の見直しにより、遅延を5〜10分から5〜10秒程度へ短縮（約30〜120倍）。
  • Real-time data trackerリアルタイムデータトラッカー開発 Designed a high-throughput system that tracks live and historical price and trade data from multiple external sources. 複数外部ソースの価格・取引データをリアルタイムおよび履歴で追跡する高スループット基盤を設計・実装。
  • Asset balance monitoring資産残高監視システム開発 Built a multi-platform balance monitor. Batching RPC requests lowered cost and latency, enabling real-time monitoring of hundreds to thousands of accounts. 複数プラットフォーム対応。RPCリクエストのバッチ化でコストとレイテンシを最適化し、数百〜数千アカウントのリアルタイム監視を低コストで実現。
  • Order-book collectionオーダーブック収集システム開発 Collects from 15+ external services and 5,000+ pairs, handling ~10 MB/s at peak. 15以上の外部サービス・5,000ペア超を対象に、ピーク時約10MB/秒のデータ処理を実現。
  • Pub/Sub migration: Redis → NATSPub/Sub基盤移行（Redis → NATS） Improved throughput and greatly reduced message loss, as verified by internal benchmarks. スループット向上とメッセージ欠損率の大幅削減を内部ベンチマークで確認。
  • Protobuf adoptionProtobuf導入 Replaced JSON with Protobuf for smaller payloads and faster serialization, with the biggest gains in order-book collection. JSONからProtobufへ移行し、ペイロード削減とシリアライズ高速化を実現（特にオーダーブック収集で効果大）。
  • Blue-Green deploymentBlue-Greenデプロイ環境構築 Set up zero-downtime deploys with nginx and Go Task. nginxとGo taskによる無停止デプロイ環境を構築。
  • FreeBSD migrationFreeBSD移行 Moved from Linux to FreeBSD, using jails for simpler operations and Prometheus with exporters for monitoring. LinuxからFreeBSDへ移行。jailによる運用効率化とPrometheus + exporterによる監視体制を導入。
  • Unified external API layer複数外部API統合基盤 Designed an abstraction layer that hides the differences between external APIs, with one interface for orders and account management. 外部サービス間のAPI差異を吸収する抽象化レイヤーを設計し、注文・口座管理を共通インターフェースで一元化。
